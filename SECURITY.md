# Security

## Reporting a problem

Please report vulnerabilities privately through the "Security" tab of the repository on GitHub ("Report a vulnerability"), not in a public issue. Say what you observed, how to reproduce it, and which version or commit you used.

## What the deck protects against

Sessions can run without approval prompts. Anything that types text into such a session can make the agent act. The deck therefore treats everything that comes out of a project as foreign.

- **Two trust levels in the local server.** The views of the type library may use the interface (`/api`). Content of a project (free artifacts, project files, the HTML of variants) is served under `/u/<read id>/` with a `sandbox` content security policy, without cookie or token, and cannot reach the interface.
- **Nothing a page sends is typed verbatim.** A page names an action and identifiers; the core composes the text for the session from the data and from fixed wording. Status values come from a fixed list.
- **The local server** listens on `127.0.0.1` only, on a random port, and requires a random token per start. Writing requests with a foreign origin are refused. The command-line interface additionally requires the token in a header, which a page in a browser cannot send.
- **Phone access** (off by default) is a separate server that only knows requests for photos and audio; the interface of the deck is not behind it. It listens on `127.0.0.1` only and requires a key from the settings, once in the address and then as a cookie; writing requests additionally need a header a foreign page cannot set, and a matching origin. You bring it to your phone yourself with a forwarder that adds HTTPS inside your own network. File names are generated by the deck, extensions come from a fixed list, only images are served back. The note typed on the phone is written to a file; the session is only told the path. The same page shows the inbox of the deck; a question can be answered there only by picking one of the options the session itself offered, never with free text.
- **Telegram** (off by default): `coop melden` sends a short plain-text message through a bot whose token and chat you enter in the settings. This is the only place where the core contacts a server on its own, and what a session reports leaves your machine. The token is stored in the settings file readable by your user only, is never handed to the window or to a session, and is removed from error texts. Messages are capped per session and hour. There is no way back: replies in Telegram reach no session.
- **Artifacts load nothing from the network.** Views of the deck are restricted to the local server; imported pages lose their references to external stylesheets, fonts and scripts.
- **Paths** are resolved inside the project; secrets such as `.env` and `.ssh` are not served.
- **Hooks of Codex**: the deck vouches per start for exactly its own four hooks by checksum. Hooks from projects and plugins stay under the CLI's own review.
- **Start commands of services** run only after you confirmed them once; a changed command needs a new confirmation.
- **Microphone**: only the window of the deck may use it, never an artifact view. Recognition runs locally.

## What it does not protect against

- The agent itself. A session without approval prompts can do whatever the CLI allows. The deck does not sandbox the CLIs.
- Content the agent reads on its own from a project (files, feedback texts). Feedback marks quote text from the page as a description, labelled as such, but an agent can still be misled by what it reads.
- Other local users or processes with access to your user account.
- The app is ad hoc signed, not notarized.
