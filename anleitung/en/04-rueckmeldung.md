# Marking and feedback

Instead of describing where something is wrong, you point at it. Every mark gets a number and your sentence. The session receives a text file that says for each mark what is meant; the picture is only attached.

## How it works

1. Open the view in question on the right. This works in every tab, including a running page.
2. Choose a tool in the toolbar and mark.
3. Write for each mark what should be different. A general remark about the view is possible.
4. Choose the target: the active session, another running one, or a new session with this task.
5. **{{ui.rueck.vorschau}}** shows the text beforehand. **{{ui.rueck.senden}}** sends it.

## The tools

| Tool | What for |
|---|---|
| **{{ui.werkzeug.zeigen}}** | Click an element. The mark knows what is meant: in typed artifacts, for example, the roadmap item or the line of the file. |
| **{{ui.werkzeug.rahmen}}** | Drag out an area. |
| **{{ui.werkzeug.pfeil}}** | Draw an arrow; what the tip points at is meant. |
| **{{ui.werkzeug.freihand}}** | Circle freely. |
| **{{ui.werkzeug.text}}** | Set a dot and label it. |

Where the deck can only estimate the reference, the feedback says so. The session then states its understanding before it builds.

## What happens next

While the session is working, the feedback waits in the queue. Once the session has dealt with it, it reports it as done. **{{ui.verlauf}}** shows all feedback on a tab, open and done, with the picture before and after.
